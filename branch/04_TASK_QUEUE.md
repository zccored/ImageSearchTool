## 2. 待办（按建议执行顺序）

### 第一优先：C2 · JPEG 解码器对照
- 目的：确认"换 JPEG 解码器"的上限（C1/C3 已给出悲观预期：JPEG 单张 p50 40.8 ms、无 progressive，预期仅 5~15%）
- 做法：`cv2`（现状，已用 libjpeg-turbo）vs `PyTurboJPEG` vs `imagecodecs`；**配对 A/B + 逐位校验 + 性能图**
- 判据：与 PNG 那轮同样形态（CPU 降、墙钟可能不动）→ 若 <5% 则不采纳

### 第二优先：缓存覆盖率（比换解码器更划算）
- 依据：缓存命中实测 **90 ms → 4 ms/张（20×）**
- 做法：统计 prep 缓存的命中率/覆盖率（全库约 2.5 万 JPEG + 约 1.5 万 PNG），找出未命中原因（首次建库必然全 miss；增量/重建应高命中）
- 产出：命中率与收益数字；若覆盖率低 → 修缓存键（现在键含 size+mtime_ns，改文件即失效，可能是命中率杀手）

### 第三优先：C4 · 更激进 DCT 缩放阈值评估（**只评估语义，先别改**）
- 现状：`_reduced_flag` 仅 >2560 → 1/2、>5120 → 1/4（且只对 JPEG/WebP）
- 候选：>1600 → 1/2
- **代价（明确）**：工作图尺寸变化 → 指纹/瓦片几何与语义变更 → **必须重建索引 + 重跑召回评估**
